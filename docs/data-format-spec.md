# Storm Charm — 資料格式規格（草案 v0.1）

吊飾韌體與網頁 App 之間的合約：兩邊照同一份寫，資料才接得起來。

狀態標示：**【已定】** 已討論並確認；**【草案】** claude 提出、尚待確認或實測；**【待查】** 需要看官方文件或實機驗證。

---

## 1. 範圍

- 吊飾端：每筆取樣資料的格式、緩衝區行為、藍牙服務。
- 網頁端：時間換算、增量同步、匯出 CSV。
- 不含：廣播封包內容（另訂）、韌體內部實作。

## 2. 基本規則

- **位元組順序：小端序（little-endian）。【草案】** nRF52840 為 ARM 小端，BLE 常見慣例亦為小端。
- **全部使用整數加固定單位**，不用浮點數。
- 格式版本 `format_version`：目前為 **1**。

## 3. 取樣資料（Sample Record）

每筆 **12 位元組**。【已定】

| 偏移 | 欄位 | 型別 | 單位 | 說明 |
|---|---|---|---|---|
| 0 | `uptime_s` | uint32 | 秒 | 取樣當下，開機後經過的秒數 |
| 4 | `pressure_pa` | uint32 | 1 Pa | 測站氣壓（BME280 量到的當地氣壓） |
| 8 | `temperature_cdeg` | int16 | 0.01 °C | 例：2345 = 23.45 °C |
| 10 | `humidity_cpct` | uint16 | 0.01 %RH | 例：6120 = 61.20 %RH |

### 欄位寬度的依據

BME280 的範圍以資料表為準，以下為估算：

| 欄位 | 範圍 | 需要的值 | 寬度 |
|---|---|---|---|
| 溫度 | −40～85 °C | −4000～8500 | int16 |
| 濕度 | 0～100 %RH | 0～10000 | uint16 |
| 氣壓 | 300～1100 hPa | 30000～110000 | uint32（超過 65535） |
| 時間 | 7 天 = 604,800 秒 | 0～604800 以上 | uint32（uint16 最多約 18 小時） |

### 讀取失敗

感測器讀取失敗時，該筆仍照時間寫入，欄位填入保留值，網頁端略過這筆的數值。【草案】

| 欄位 | 保留值 |
|---|---|
| `temperature_cdeg` | `0x8000`（−32768） |
| `humidity_cpct` | `0xFFFF` |
| `pressure_pa` | `0` |

### 範例（測試向量）

`uptime_s = 3600`、`pressure_pa = 101325`、`temperature_cdeg = 2345`、`humidity_cpct = 6120`

```
10 0E 00 00  CD 8B 01 00  29 09  E8 17
```

韌體與網頁都應能用這組位元組得出同樣的數值。

## 4. 取樣與緩衝區

| 項目 | 值 | 狀態 |
|---|---|---|
| 取樣間隔 | 120 秒（2 分鐘） | 【已定】 |
| 緩衝區位置 | RAM | 【草案】 |
| 緩衝區容量 | 5,040 筆（約 7 天，60,480 位元組，約 59 KB） | 【草案】 |
| 寫滿時 | 覆蓋最舊的資料（環形） | 【草案】 |
| 重開機 | RAM 清空，序號與開機秒數從 0 開始 | 【已定】（RAM 方案下） |
| 同步頻率 | 至少每天一次 | 【已定】 |

日後改存 flash 時，重開機後資料會保留，需補上跨開機的區段邊界，屆時升版（見第 9 節）。

## 5. 序號

- 每筆資料有一個序號 `seq`（uint32），**不另外儲存**，由緩衝區位置推得。
- 開機後第一筆為 `seq = 0`，之後每筆加 1。
- `oldest_seq`：緩衝區中最舊那筆的序號；`next_seq`：下一筆將寫入的序號。
- 資料筆數 = `next_seq − oldest_seq`。

## 6. 時間換算（網頁端）

吊飾沒有真實時鐘。同步時網頁記一組**錨點**：

```
錨點 = (boot_id, device_uptime_s, host_time)
```

某筆資料的實際時間：

```
實際時間 = host_time − (device_uptime_s − record.uptime_s)
```

- 每次同步重新取錨點，吊飾計時的微小漂移不會累積。
- `boot_id` 與上次不同，代表吊飾重開機過：新資料另算一個區段，不接在舊資料後面，並標示「這段時間吊飾曾重開機或沒電」。

## 7. 藍牙服務

自訂一個服務（UUID 待產生【待查】），包含五個特徵：

| 特徵 | 權限 | 大小 | 內容 |
|---|---|---|---|
| 裝置狀態 | 讀 | 20 位元組 | 見 7.1 |
| 裝置資訊 | 讀 | 10 位元組 | 見 7.2（靜態） |
| 即時值 | 讀 | 12 位元組 | 讀取當下量一次，格式同取樣資料 |
| 控制 | 寫 | 變動 | 見 7.4 |
| 資料 | 通知 | 變動 | 見 7.5 |

### 7.1 裝置狀態（20 位元組）

| 偏移 | 欄位 | 型別 | 說明 |
|---|---|---|---|
| 0 | `format_version` | uint8 | 目前為 1 |
| 1 | `flags` | uint8 | 保留，填 0 |
| 2 | `boot_id` | uint32 | 每次開機產生的隨機值 |
| 6 | `uptime_s` | uint32 | 目前開機後秒數 |
| 10 | `battery_mv` | uint16 | 電池電壓，毫伏（讀取方式見第 11 節） |
| 12 | `oldest_seq` | uint32 | 見第 5 節 |
| 16 | `next_seq` | uint32 | 見第 5 節 |

總長壓在 20 位元組以內，避免預設連線下需要長讀取。

### 7.2 裝置資訊（10 位元組，靜態）

| 偏移 | 欄位 | 型別 | 說明 |
|---|---|---|---|
| 0 | `sample_interval_s` | uint16 | 取樣間隔，目前 120 |
| 2 | `buffer_capacity` | uint32 | 緩衝區容量（筆），目前 5040 |
| 6 | `fw_major` | uint8 | 韌體版本 |
| 7 | `fw_minor` | uint8 | |
| 8 | `fw_patch` | uint8 | |
| 9 | `sample_size` | uint8 | 每筆位元組數，目前 12 |

網頁用 `sample_size` 切割資料封包，日後格式加欄位時舊網頁較不易出錯。

### 7.3（選用）標準電池服務

可另外提供藍牙標準的電池電量（百分比），讓其他藍牙工具也讀得到。電壓換算百分比只是估計，精確值以 `battery_mv` 為準。【草案】

### 7.4 控制（寫入）

| 位元組 | 內容 |
|---|---|
| 0 | 指令碼 |
| 1… | 參數 |

| 指令碼 | 名稱 | 參數 | 行為 |
|---|---|---|---|
| `0x01` | `START_SYNC` | `from_seq` uint32 | 從 `from_seq` 開始送資料；若小於 `oldest_seq`，改從 `oldest_seq` 開始（代表中間有資料被覆蓋） |
| `0x02` | `STOP` | 無 | 停止送資料 |

### 7.5 資料（通知）

每個通知封包：

| 偏移 | 內容 |
|---|---|
| 0 | `first_seq`（uint32）：這包第一筆的序號 |
| 4 | 若干筆取樣資料，每筆 `sample_size` 位元組 |

- 每包可放的筆數 = floor((通知可用位元組 − 4) ÷ 12)。通知可用位元組 = 協商後的 MTU − 3。
- **結束標記**：只有 4 位元組標頭、沒有資料的封包，其 `first_seq` 等於 `next_seq`。
- **掉包處理**：網頁發現封包的 `first_seq` 不連續，就再送一次 `START_SYNC` 從缺的位置重要。
- 網頁以 `first_seq` 檢查連續性，因此不需要每包確認。

### 容量與時間估算

| 通知可用位元組 | 每包筆數 | 同步 5,040 筆（7 天） | 同步 720 筆（1 天） |
|---|---|---|---|
| 20（預設，未協商） | 1 | 5,040 包 | 720 包 |
| 241（MTU 244） | 19 | 266 包 | 38 包 |

實際協商出的 MTU 與傳輸速度要實測。【待查】

## 8. 網頁端同步流程

```
連線
 → 讀「裝置狀態」，取得 boot_id、uptime_s、oldest_seq、next_seq、電池
 → 記錄錨點
 → boot_id 與上次相同？
     是 → from_seq = 上次收到的最後序號 + 1
     否 → 新區段，from_seq = oldest_seq
 → 寫「控制」START_SYNC(from_seq)
 → 收「資料」通知，檢查序號連續性，寫入瀏覽器儲存
 → 收到結束標記，斷線
```

## 9. 版本與相容規則

- 格式有不相容的改動，就加大 `format_version`。
- 相容的擴充只往**尾端**加欄位，網頁遇到不認識的尾端位元組要略過。
- 保留位元（如 `flags`）填 0，網頁不得依賴其值。
- 之後加感測器（如閃電、光），計畫以新的取樣資料型別或新的特徵加入，並透過 `sample_size` 與版本號讓舊網頁不會誤判。

## 10. 匯出 CSV 與分析腳本

網頁匯出欄位：

| 欄位 | 說明 |
|---|---|
| `datetime` | 換算後的實際時間（ISO 8601） |
| `boot_id` | 所屬開機區段 |
| `seq` | 序號 |
| `temperature` | °C |
| `relative_humidity` | %RH |
| `station_pressure` | hPa（`pressure_pa ÷ 100`） |
| `dew_point` | °C，由溫度與濕度算出（例如 Magnus 公式） |
| `precipitation` | 留空，之後對照測站降雨資料時填入 |

**注意：** `analysis/analyze_station_rain.py` 假設資料是**逐時**且規則的。吊飾每 2 分鐘一筆，要先重新取樣成逐時（例如取小時平均）才能直接餵進去，或之後另外調整腳本以支援分鐘級資料。
