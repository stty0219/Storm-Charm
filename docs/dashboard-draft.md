# Storm Charm — 戰情室畫面草稿（草案 v0.1）

階段 A 的電腦版網頁介面：同步吊飾資料、監看裝置狀態、顯示降雨風險與證據。資料來源與欄位定義見 [`data-format-spec.md`](data-format-spec.md)。

狀態標示：**【已定】** 已討論並確認；**【草案】** 我提出、尚待確認；**【待查】** 需官方文件或實測。

---

## 1. 目的與原則

- 階段 A 供電腦使用，**資訊完整優先**，不需要手機那樣簡約。
- 風格：深色背景、等寬字體、方框分區（取自你的文字介面草圖）。
- **分級加證據，不給肯定語氣。**【已定】風險等級旁一律附上依據與歷史精準度。
- 所有顯示的值都能由資料格式規格直接得出，不依賴額外資料。

## 3. 各區塊與資料來源

| 區塊 | 顯示內容 | 來源 | 備註 |
|---|---|---|---|
| 標題列 | 電量百分比與電壓 | 裝置狀態 `battery_mv` | 百分比由電壓估算，見第 5 節 |
| 同步列 | 連線按鈕、上次同步時間、同步狀態 | 網頁自己記錄 | Web Bluetooth 需使用者點按才能連線，所以一定要有按鈕 |
| 即時體感 | 溫度、濕度、氣壓、露點差 | 即時值特徵；露點差由網頁計算 | 同步後也可改用最新一筆歷史資料 |
| 降雨風險評估 | 等級、依據、歷史參考 | 由最新資料計算 | 規則見第 4 節 |
| 趨勢 | 濕度、溫度、氣壓、露點差 | 瀏覽器儲存的歷史資料 | 規則見第 6 節 |
| 裝置狀態 | 運作時間、緩衝區用量、開機次數、韌體版本、開機識別碼 | 裝置狀態與裝置資訊 | 開機次數由網頁依 `boot_id` 變化累計 |
| 資料與匯出 | 原始資料表、匯出 CSV | 瀏覽器儲存 | CSV 欄位見規格第 10 節 |

## 4. 風險等級顯示規則

**主軸是濕度與露點差的絕對值，氣溫驟降只加強、不單獨觸發。**【已定】數值是依 2025 臺北站逐時資料得出的初始值，需以吊飾資料驗證，見 README 第 12 節。

| 等級 | 條件【草案】 | 歷史參考（臺北站 2025、逐時資料） |
|---|---|---|
| 低 | 以下條件皆不成立 | — |
| 中 | 濕度 ≥ 85 % | 觸發後約 20 %（約每 5 次有 1 次）在 2 小時內下雨 |
| 高 | 濕度 ≥ 90 %，或露點差 ≤ 2 °C | 約 24～26 %（約每 4 次有 1 次） |
| 加強 | 在「中」以上，且氣溫 2 小時降 ≥ 2 °C | 樣本小（一年 22 次），只當線索 |

- 「加強」標記出現時，若原為「中」則升為「高」。【草案】
- **畫面必須同時顯示「歷史參考」那一行。**【已定】「高」容易被讀成「會下雨」，但歷史上每 4 次警報只有約 1 次在 2 小時內下雨。
- 歷史參考的數字來自固定測站的逐時資料；吊飾累積足夠資料後，改用自己的結果。【待查】
- 氣壓趨勢目前不參與判斷，但**持續顯示與記錄**，供之後驗證。【已定】

### 依據的顯示

列出實際成立的條件與當前值，例如：

```
依據：濕度 92 %（≥ 90 %）、露點差 1.4 °C（≤ 2 °C）
```

沒有條件成立時顯示「目前沒有明顯的降雨訊號」，不說「不會下雨」。

## 5. 計算與換算

### 露點與露點差

Magnus 公式（係數 a = 17.62、b = 243.12，T 為攝氏）：

```
γ  = ln(RH / 100) + a·T / (b + T)
Td = b·γ / (a − γ)
露點差 = T − Td
```

測試向量（網頁與日後的 C 版本應得出相同結果）：

| T（°C） | RH（%） | 露點（°C） | 露點差（°C） |
|---|---|---|---|
| 25.0 | 60 | 16.69 | 8.31 |
| 21.4 | 90 | 19.69 | 1.71 |
| 21.4 | 92 | 20.05 | 1.35 |

露點差一律由公式計算，不寫死。

### 電量百分比

- 精確值以電壓為準；百分比只是估計，不可當成精確的剩餘電量。【已定】
- 電壓換算百分比採分段查表。【草案】實際曲線取決於電池與負載，需以自己的放電紀錄校正。【待查】
- 低電量提示：≤ 20 % 顯示「建議拿進房間充電」（黃色）、≤ 10 % 顯示紅色。【草案】門檻待依續航實測調整。

## 6. 趨勢圖

| 項目 | 規格 |
|---|---|
| 預設範圍 | 24 小時【草案】；可切換 6 小時、24 小時、7 天 |
| 圖表 | 濕度、溫度、氣壓、露點差，**各一張獨立的小圖**，單位不同不共用座標 |
| 資料點 | 2 分鐘一筆；7 天範圍時降採樣（例如每 10 分鐘取平均）以免畫面過密 |
| 空缺 | 兩次取樣間隔超過預期（例如 > 3 倍）就斷線，不連起來 |
| 重開機 | `boot_id` 改變處畫一條垂直標記，註明「吊飾重開機或沒電」 |
| 氣壓 | 保留顯示；氣壓有明顯日週期，圖上不做趨勢判斷 |

## 7. 同步狀態與警示

| 狀態 | 顯示 |
|---|---|
| 已連線，同步中 | 進度（已收筆數 / 預期筆數） |
| 已同步 | 上次同步時間 |
| 超過 24 小時未同步 | 警示：緩衝區只保留約 7 天，且電池沒電會遺失 RAM 資料【草案】 |
| 偵測到重開機（`boot_id` 改變） | 橫幅：吊飾已重開機，新資料另分區段 |
| 緩衝區用量 | 顯示 `筆數 / 容量`，接近滿載時警示 |
| 資料空缺 | 同步時發現 `from_seq` 小於 `oldest_seq`，提示「中間有資料被覆蓋」 |
| 瀏覽器不支援 Web Bluetooth | 顯示說明，建議使用支援的桌面瀏覽器 |

## 8. 實作提醒

- **用 CSS 排版，不用字元畫框線。** 中文字元寬度與英文不同，`+---+` 與 `|` 的方框在右側容易錯位。保留深色背景、等寬字體、方框外觀即可，用 CSS 的邊框與格線。
- **避免依賴表情符號。** 不同系統顯示不一致，改用文字或簡單的圖示。
- 顏色以色彩變數定義，風險等級不只靠顏色區分，同時用文字標示。
- 時間顯示用本機時區，儲存用 ISO 8601。
- 風險判斷模組寫成獨立、可測試的 JavaScript 模組，用測站 CSV 與上面的測試向量驗證。
