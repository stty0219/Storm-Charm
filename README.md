# Storm Charm — 專案提案

> **Storm Charm**：一個掛在包包上的 BLE 環境感測吊飾，持續記錄身處環境的物理量，在「感覺快下雨」的那一刻，提供實測數據作為佐證。

---

## 1. 背景與動機

走在路上有時會「感覺快下雨了」（空氣悶濕、氣壓低、突然變涼），但天氣預報的範圍較大，無法對應「此時此地」的體感，也沒有具體數據能佐證這個感覺。

現有的降雨 App 多半依賴雷達回波外推，回答的是「這個區域會不會下雨」。本專案想回答的是另一個問題：

**以目前身處的物理環境來看，現在是不是快下雨了？**

## 2. 目的

1. 製作一個隨身、低功耗的環境感測裝置，持續記錄溫度、濕度、氣壓。
2. 以「變化趨勢」而非單點絕對值，判斷降雨風險是否升高。
3. 在 App 上輸出「風險分級＋證據」，讓使用者看到判斷依據，而不是一個黑盒子的機率。
4. 作為日常可實際使用的小工具，並累積資料驗證判斷規則的有效性。

## 3. 核心概念

### 3.1 為什麼不能只看濕度

相對濕度高不等於會下雨（霧、梅雨季、海邊都可能超過 90%）。單一濕度數值預測力有限，這是本專案設計的出發點。

### 3.2 看趨勢，多訊號綜合

人之所以「感覺快下雨」，是在感知多個物理量的變化。本專案用感測器量化這些訊號：

| 體感 | 物理量 | 判斷方式（初始經驗值，需以實際資料調整） |
|---|---|---|
| 空氣悶、黏 | 相對濕度、露點差（溫度 − 露點） | 露點差變小且持續縮小 |
| 氣壓低、頭悶 | 氣壓下降趨勢 | 1～3 小時內明顯下降 |
| 突然變涼 | 溫度驟降 | 短時間內降數度 |
| 遠處雷擊（後期） | 閃電偵測 | 有訊號即為強對流警訊 |

單一條件觸發不算，**多個條件同時成立才提高風險等級**。

### 3.3 輸出形式：分級加證據

不輸出精確的「降雨機率 73%」（假精確），而是分級並列出依據，例如：

> 注意：氣壓 2 小時降 2.1 hPa，露點差 1.8°C，溫度 15 分鐘降 3°C → 降雨風險：高

## 4. 方法與系統架構

### 4.1 設計原則：儲存後同步

吊飾是資料的主人，手機只是來讀取。

- **吊飾**：定時取樣，存入環形緩衝區，平常只做低頻 BLE 廣播（可帶粗略風險等級）。
- **手機 App**：開啟後掃描並連線吊飾，批次下載歷史資料後斷線。
- **趨勢計算與風險判斷**：在 App 端以完整資料計算，調整門檻只需更新 App，不必重刷韌體。

這樣不需要一直連線，不佔用手機的藍牙連線額度，也較省電、不怕斷線。吊飾持續記錄，因此使用者走出門、打開 App 時，過去數小時的趨勢已經存在裝置中。

### 4.2 架構圖

```
[BME280 溫濕壓] → MCU (nRF52840) → BLE
        │ 定時取樣、環形緩衝區（相對時間戳記）
        ▼
[iPhone App] → 連線、批次下載歷史 → 本機資料庫
        │ 趨勢計算（氣壓、露點差、溫度變化）
        ▼
   風險分級 ＋ 證據顯示
```

### 4.3 平台選擇

- 手機為 iPhone，因 iOS Safari 不支援 Web Bluetooth，**PWA 不可行**，App 採原生開發。
- 第一版**不需要後端伺服器與資料庫**，資料存於手機本機。

## 5. 第一版規格

### 硬體

| 項目 | 選擇 | 備註 |
|---|---|---|
| MCU 板 | nRF52840 開發板（如 Seeed XIAO nRF52840） | 內建 BLE、體積小、含鋰電池充電電路 |
| 感測器 | BME280 | 溫度、濕度、氣壓，I2C |
| 電池 | 小型鋰電池（約 150～300 mAh） | 續航需實測 |
| 外殼 | 小盒或 3D 列印 | 需通風孔，遠離體溫與電池發熱 |

### 韌體

- 定時取樣（BME280 forced mode），每 1～5 分鐘一筆
- 環形緩衝區，以開機後相對時間作為時間戳記
- BLE：低頻廣播；連線後提供「讀即時值」與「批次讀歷史」
- 開發環境：Zephyr（nRF Connect SDK）或 Arduino

### iOS App

- Swift + SwiftUI + CoreBluetooth
- 掃描、連線、批次下載後斷線
- 相對時間換算為實際時間，存入本機資料庫
- 計算氣壓趨勢、露點差、溫度變化，輸出風險等級與證據
- 顯示即時值與趨勢圖
- 以免費 Apple ID 裝機測試（簽章需定期重裝），長期使用再考慮開發者帳號（US$99/年）

### 預估成本

硬體原型約 NT$600～1,000。

## 6. 第一版不做

後端伺服器、雲端同步、閃電偵測、光感測、「有下／沒下」標註、背景自動同步。待基本版驗證後再評估。

## 7. 開發順序

1. 開發板接 BME280，以序列輸出確認讀數正常
2. 加入緩衝區與 BLE 服務，用 nRF Connect App 驗證資料可讀取
3. 開發 iOS App 接收並顯示
4. 加入趨勢計算與風險分級
5. 日常攜帶並記錄資料，對照實際降雨情況調整門檻

## 8. 風險與限制

| 項目 | 說明 | 因應 |
|---|---|---|
| 移動中的雜訊 | 口袋、體溫、日曬、進出室內都會干擾讀數 | 外殼設計隔熱通風；偵測劇烈環境變化時忽略該段資料 |
| 感測器反應與自熱 | 濕度感測器反應需數秒至數十秒，裝置發熱影響溫度 | forced mode 降低發熱；實測校正 |
| 門檻為經驗值 | 氣壓、露點差等門檻需以實際資料驗證 | 持續記錄並與降雨紀錄對照 |
| 局部對流難以預測 | 突發雷陣雨可能沒有明顯前兆 | 定位為「增加佐證」而非保證；後期可加閃電偵測 |
| iOS 背景限制 | App 在背景的 BLE 行為受限 | 第一版以開 App 時同步為主；後續評估 state restoration |
| 續航未知 | 理論值不可靠 | 以實測為準 |

## 9. 預期成果與價值

- 一個可日常攜帶使用的降雨徵兆偵測吊飾。
- 一份自己蒐集的環境資料集，可用來驗證「哪些訊號對降雨有預測力」。
- 一個端到端的作品：感測器驅動、低功耗 BLE 韌體、iOS App、資料處理與評估，適合作為 GitHub 專案展示。

## 10. 後續可擴充方向

- 加入閃電偵測（如 AS3935）與光感測，補強對流性降雨的預警
- 加入「有下／沒下」一鍵標註，累積標註資料以調整門檻
- 背景自動同步與通知
- 雲端備份、多裝置同步，或與雷達降雨資料對照分析

## 11. 待確認事項

- 取樣頻率與歷史保存時長
- 廣播封包要放哪些欄位
- 硬體採購清單
